## Implemented candidate behavior

The old editor called absent/api/upload/image. Existing generic/storage/creations/gallery upload rails obtain public URL references and are unsuitable for private manuscripts. The new direct-upload route authenticates the current user and owned document before reading bounded20KiB metadata or touching storage. Both route and SQL bind owner/project/document; SQL locks current document scope against updates while reserving/completing. Upload capabilities permit one deterministic path, exact claimed maximum bytes, one MIME type, ten-minute expiry and no overwrite/random suffix. No storage token reaches the client.

Originals support PNG/JPEG/WEBP up to10MiB, without expanding Imagine's existing3MiB/base64 JSON contract or rewriting its applied migration. A new document table shares the existing imagine_storage_accounts lock/capacity. No quota defaults or account provisioning are added. Missing write-enable, private token, admin configuration or capacity refuses saving. Ready status requires actual private read, exact byte count/MIME/SHA256 and full sharp decode with16million-pixel/single-frame bounds. Unknown outcomes retain immutable bytes/reservations and retry identity.

The client derives the stable image ID from owner/project/document, original digest, MIME and filename. It reconciles completion before another put, then reads after success or uncertain put acknowledgement. Late account/document results are rejected. The editor retains a failed File in the mounted owner workspace, exposes retry/original download, and warns before leaving with a pending image. It inserts a private application handle only after the exact ready receipt. This is not an IndexedDB/offline original outbox; mounted-memory loss/device recovery still needs acceptance and a deliberate storage contract.

Readback verifies the complete bounded original before returning a pull-driven64KiB-chunk stream, avoiding a buffered10MiB function response. [Vercel's official body-limit guide](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions) recommends streaming for larger responses. A native actual10MiB stream preserves the digest and bounded chunk sizes; real hosted provider/function behavior is still unverified. No signed download URL or public handle is introduced.

Portable export reads only image handles from the current document, validates owned ready metadata/digests, embeds original bytes in offline HTML and includes editable document JSON plus source/rights-unverified provenance. External/foreign/legacy Imagine references fail explicitly rather than silently exporting broken images. Existing draft JSON recovery remains available. Bounds: oneMiB draft,32 distinct originals,40MiB combined media,10000 nodes and64 levels. No scripts/remote fetch/form execution; exported creator text/attributes are escaped. Unsupported rich nodes keep their structured JSON but need output fidelity review. Draft changes during asynchronous export stop the download. Cross-document/imported legacy media and a useful import flow remain work.
