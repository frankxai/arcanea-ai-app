## Coordination model (proposed, locked unless Frank overrides)

**One Lumina (Opus) session = swarm queen.** Coordinates, decides, writes plans.
**Subagents (Sonnet/Haiku) inside that session = workers.** Per-repo execution in isolated worktrees. Don't multiply RAM cost the way separate Claude Code instances do. This honors `feedback_ops_workflow` (max 4-5 instances) and `CLAUDE.md` (16 GB RAM, max 4-5 instances).

**Per-repo state lives where the work happens:**
- Per-repo planning: `<repo>/planning-with-files/SPRINT_*.md` (when active)
- Cross-repo dashboard: `Arcanea/.arcanea/projects/sprints/W19.md` (this file as primary)
- Persistent wisdom: Obsidian vault
- Captured runtime prompts: Notion (when capture pipeline restored)

**Daily rhythm:**
- Morning: `/dawn` for cross-repo status + last handover's recommended next move
- Evening: `/handover` writes status + next-session prompt to `docs/ops/HANDOVER-YYYY-MM-DD.md`
- Friday: `/repo-triage` runs full audit across all 11 active repos, writes single digest
