# Founder Mode

Founder mode compresses decision loops from quarters to hours. Manager mode is the inverse.

The difference is not titles or org charts—it's loop closure time. In manager mode, a decision follows a cycle: problem surfaces → escalation → committee → consensus → decision → implementation → feedback. Each stage adds days. A code decision takes 2-4 weeks.

In founder mode, the founder holds the problem, the constraints, the market, and the solution in head-space simultaneously. No escalation. No consensus. The decision happens when the problem is stated because the founder's priors already contain 90% of the context. Implementation follows in days.

This is why founders scale code-to-revenue 3-5x faster than teams of the same size. Not because founders are smarter; because feedback tightens.

The constraint: founder mode *requires* the founder to be the bottleneck on decisions that matter. The moment the founder tries to delegate "to scale," they shift toward manager mode, and the loop opens back up. The trade: bottleneck stays tight, but throughput is capped at what one person can hold in head-space. For Arcanea that's about 13 surfaces + 12 domains + Prompt OS + 7 scheduled skills. Any more and decisions start queuing.

The recovery: once you hit the ceiling, you don't hire a "VP of Decisions." You ship things that can decide for themselves: smaller units with clear invariants, agents with policy, systems that self-route. You push decision-making to the edge.
