# PARA

**Four top-level folders for mutable work.** Projects (time-bound), Areas (ongoing), Resources (reference), Archive (dead).

## The cut

- **P**rojects — time-bound, deliverable-driven. Closes when shipped.
- **A**reas — ongoing, no end date. Brands + life domains.
- **R**esources — reference. Book notes, frameworks, people dossiers.
- **A**rchive — graveyard. Searchable, not navigable.

## Why it matters

PARA separates **work-in-progress** from **knowledge**. Work moves (Projects → Archive). Knowledge stays (Resources, Areas). Second-brain systems that don't separate these turn into mud.

## Where it shows up

- `06-Projects/` → P
- `07-Areas/` → A
- `08-Resources/` → R
- `09-Archive/` → A

## What we adopt

- Four-folder partition for mutable work
- Project close → Archive move ritual
- Areas as fixed set (8 in this vault — 5 brands + 3 life areas)

## What we don't adopt

- Full CODE process (Capture-Organize-Distill-Express) — Prompt OS replaces this
- PARA inside every app — here it's vault-level only

## Anti-pattern

Using PARA as the whole system. PARA handles mutable work. Knowledge (durable atoms) needs Karpathy-style atomic notes. Navigation needs LYT MOCs. PARA alone is incomplete.
