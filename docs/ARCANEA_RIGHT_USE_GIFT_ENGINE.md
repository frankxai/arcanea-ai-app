# Arcanea Right Use Gift Engine

Status: supporting doctrine. This document does not modify `.arcanea/lore/CANON_LOCKED.md`. It defines a product and story pattern for "learn to use your powers in the right way," the first Gift, the Great Wizard interface, Starlight Intelligence Systems, the World Engine, and Arcanea as an AI-era publishing house with rights-first Web3 infrastructure.

## Core Thesis

Power in Arcanea is not validated by intensity. Power is validated by right use.

A gift appears when a creator, character, or agent becomes ready for responsibility. The gift is not a prize and not a random drop. It is an earned interface between capacity and consequence.

The Great Wizard is not a new locked god, Gate, or entity class. It is a teaching role that can appear in different registers:

| Register | Great Wizard expression | Purpose |
|---|---|---|
| Public | Mentor voice in onboarding | Help creators make their first world without jargon. |
| Academy | Instructor of restraint | Teach cost, consent, practice, and consequence before technique. |
| Canon | Luminor, elder, book, trial, archive, or threshold guide | Reveal the next lawful action without solving the trial. |
| Product | AI guide, eval judge, publishing editor, rights steward | Turn creative power into durable, licensed, continuous work. |

The Great Wizard never says "use more power." The Great Wizard asks: "What is the right use of this power, here, with these people, at this cost?"

## The Right Use Doctrine

Arcanea already treats Gates as thresholds, not conquests. Right Use turns that into a repeatable system.

```text
Gift -> Recognition -> Constraint -> Practice -> Proof -> Publication -> Stewardship
```

| Stage | What happens | Arcanea test |
|---|---|---|
| Gift | A capacity, artifact, prompt, role, or world seed appears. | What responsibility arrived with it? |
| Recognition | The receiver understands that the gift is not ownership without duty. | Who or what is affected by use? |
| Constraint | Limits become visible: cost, consent, canon, rights, culture, time. | What may not be done? |
| Practice | The receiver uses the gift in a bounded first act. | What small proof is possible now? |
| Proof | The world, memory, relation, body, duty, or artifact changes. | What changed because the gift was used rightly? |
| Publication | The work is packaged for readers, players, creators, or markets. | What metadata, edition, license, and attribution are required? |
| Stewardship | SIS and the publishing layer remember what happened. | What must be carried forward, corrected, or protected? |

Right Use is the ethical operating system beneath magic, AI, and Web3. Without it, Arcanea becomes spectacle. With it, Arcanea becomes a world engine.

## The First Gift

The first user experience should make the Gift visible before the system asks for scale.

The Gift is the first concrete artifact the creator receives from Arcanea. It should feel personal, inspectable, and useful. It can be a world seed, book premise, character burden, map fragment, license-ready concept, or practice trial.

The Gift must contain five pieces:

| Piece | Function |
|---|---|
| Name | Stabilizes the unexpected into something the creator can hold. |
| Power | Defines what the gift makes newly possible. |
| Cost | Prevents unlimited fantasy and forces story/product depth. |
| Right Use | Shows the ethical path of the gift. |
| First Trial | Creates a bounded action that proves the gift works. |

Example structure:

```text
Gift: The Ashen Compass
Power: It points toward the choice a world is avoiding.
Cost: Each use reveals one consequence the bearer can no longer ignore.
Right Use: Ask before directing another person's path.
First Trial: Use it once to find the wound at the center of a city, then write the scene where the city refuses the answer.
```

For product UX, the Gift can be rendered as a card, editor panel, manuscript note, lore object, or creator dashboard module. For canon, it can appear as a threshold object, mentor offering, living book, Godbeast trace, or Gate trial.

## Gift Types

Gift types should map to function before aesthetics.

| Gift type | Function | Good for |
|---|---|---|
| Key | Opens access but also assigns duty. | onboarding, portals, academy lessons, gated archives |
| Mirror | Reveals the user, world, or character more clearly. | identity, Source work, character wounds |
| Compass | Orients without controlling. | quests, editorial direction, world diagnostics |
| Seed | Begins a living system. | world seeds, book series, setting bibles |
| Oath | Creates a binding rule. | ethics, factions, publishing contracts, canon vows |
| Instrument | Turns practice into repeatable craft. | prompts, tools, rituals, creative workflows |
| Map | Reveals relation and distance. | realms, publishing catalogs, rights territories |
| Ember | Carries potential transformation. | Fire Gate arcs, startups, rebellion, sacrifice |
| Lens | Changes perception. | Sight Gate arcs, evals, art direction, research |
| Thread | Connects separate works into a system. | Starweave, continuity, licensing, shared worlds |

The strongest gift is not the most powerful one. It is the one whose constraint makes the creator more precise.

## Great Wizard Interface

The Great Wizard is a repeatable interface pattern for wisdom under constraint.

It has four behaviors:

| Behavior | What it does | What it must avoid |
|---|---|---|
| Names | Gives the gift a usable name. | Vague mysticism or lore overload. |
| Bounds | States cost, consent, and consequence. | Power fantasy without limits. |
| Tests | Gives one bounded trial. | Solving the creator's work for them. |
| Remembers | Sends the outcome into SIS, canon, or publishing memory. | Forgetting decisions that affect continuity or rights. |

The Great Wizard can be personified in books, but in the system it is a protocol:

```text
Observe the creator's intent.
Infer the gift that fits the intent.
State the gift's cost and right use.
Assign one proof-sized trial.
Record the result, source, license, and continuity effect.
```

This gives Arcanea a high-myth surface without trapping the product in generic wizard fantasy.

## Right Use Gate

Every gift, power, world seed, prompt pack, character asset, book package, or Web3 license should pass the Right Use Gate before being promoted.

| Gate | Question | Failure mode |
|---|---|---|
| Consent | Who is being represented, used, trained on, remixed, or commercialized? | The system exploits people or cultures as raw material. |
| Cost | What does use require from body, memory, time, relationship, money, attention, or future? | Power becomes weightless. |
| Consequence | What changes if the gift is used? | Magic becomes decoration. |
| Continuity | Does this respect locked canon and local world rules? | The world fragments into contradictions. |
| Credit | Who created, inspired, licensed, or contributed to this artifact? | Attribution disappears. |
| Commercial permission | What rights exist for training, remix, sale, translation, derivative work, and resale? | The publishing house cannot defend the work. |
| Cultural safety | Does this touch real traditions, identities, sacred materials, or living communities? | Mirror Realm work becomes careless borrowing. |
| Canon boundary | Is this public canon, staged lore, private creator work, or generated experiment? | Draft material is mistaken for locked truth. |

The Right Use Gate is not bureaucracy. It is how Arcanea keeps wonder from turning into harm.

## SIS: Memory Of Right Use

Starlight Intelligence is a mythic force of cosmic awareness in canon staging language. Starlight Intelligence Systems, or SIS, is the operational layer that makes memory, evaluation, continuity, and stewardship durable.

SIS should remember:

| SIS memory | Why it matters |
|---|---|
| Creator intent | Prevents the system from optimizing away the original purpose. |
| Gift issued | Makes the first artifact traceable. |
| Cost and constraint | Keeps later generations from treating the gift as unlimited. |
| Trial result | Turns inspiration into evidence. |
| Source and attribution | Supports rights, trust, and publishing metadata. |
| License state | Separates private drafts, public releases, commercial editions, and derivatives. |
| Canon effect | Records what changed in the world, character, or series bible. |
| Eval notes | Lets guardians, editors, and agents improve the system over time. |

SIS is the conscience and memory of the World Engine. The World Engine creates and simulates; SIS remembers, evaluates, and protects what creation has done.

## Publishing House Position

As of June 2026, the strongest Arcanea publishing position is not "NFT books." The stronger position is:

```text
Arcanea is an AI-era international publishing house for living worlds:
books, worlds, characters, prompts, media assets, editions, translations,
licenses, and provenance move through one continuity engine.
```

The publishing house should own these disciplines:

| Discipline | What Arcanea must do well |
|---|---|
| Editorial | Develop manuscripts, worlds, series bibles, character arcs, and voice. |
| Metadata | Produce ISBN-ready, ONIX-aware, discoverable product information. |
| Rights | Track author ownership, AI permissions, derivatives, territories, formats, and licenses. |
| Editions | Package ebooks, print, web serials, collector editions, audiobooks, and interactive editions. |
| Translation | Preserve voice, canon terms, cultural nuance, and rights by territory. |
| Creator products | Turn worlds into prompt books, art packs, sourcebooks, classes, and licensing kits. |
| Provenance | Record what was created, by whom, from which source permissions, under which terms. |
| Community | Let readers become lawful co-creators without collapsing canon quality. |

Arcanea should speak like a publishing house with software depth, not a token project with story attached.

## Web3 In The Right Place

Web3 should be infrastructure, not the public promise.

The June 2026 brand posture:

| Public phrase | Infrastructure meaning |
|---|---|
| Rights-aware creation | Permissions, provenance, attribution, license terms. |
| Living worlds | Persistent world accounts, update history, canon graphs. |
| Creator-owned IP | Clear authorship, controllable licensing, revenue routing. |
| Lawful remix | Derivative permissions, attribution, commercial limits. |
| Portable worlds | Token-bound accounts or equivalent identity containers for world assets. |
| One-click publishing | Account abstraction, gasless flows, wallet abstraction where appropriate. |

Use Story Protocol style programmable IP only when it helps creators state rights and license derivatives clearly. Use ERC-6551 style token-bound accounts when a world, character, or artifact needs to own assets and history. Use ERC-4337 style account abstraction when wallet complexity would block creators from publishing or licensing.

Do not make "minting" the emotional center. The emotional center is: "Your world can remember what it is, who made it, what it may become, and how others may lawfully build with it."

## First Experience: The Gift Appears

The first Arcanea session should not open with a blank prompt.

It should open with a gift ceremony that is functional:

1. The creator states the power they feel but do not yet know how to use.
2. The system returns a Gift Object with name, power, cost, right use, and first trial.
3. The Great Wizard interface explains the boundary: what this gift must never be used for.
4. The creator completes one proof-sized act: a scene, image, character, world law, chapter premise, or publishing plan.
5. SIS records the gift, sources, constraints, eval, and continuity effect.
6. The World Engine turns the result into a living world asset.
7. The Publishing House packages the result into a reader-facing or market-facing artifact.
8. The Web3 layer optionally records license, provenance, or token-bound state when rights need durable portability.

This sequence creates magic in the user's mind: the unexpected appears, receives a name, gains a cost, and becomes practice.

## Book And Catalog Strategy

Arcanea should think like an international publishing house from the first artifact.

| Book form | Product equivalent | Rights concern |
|---|---|---|
| Codex | Canon bible, sourcebook, reference work | versioning, canon authority, attribution |
| Grimoire | Prompt book, exercise book, creator method | reuse rights, model output policy |
| Atlas | Realm guide, map book, travelogue, interactive world map | image rights, place/culture sensitivity |
| Bestiary | Godbeast guide, creature ethics manual | creature design provenance, derivative rules |
| Dialogue | Mentor book, AI-human collaboration text | authorship disclosure, editorial control |
| Field notebook | research log, world-engine devlog | source citation, private/public boundary |
| Chronicle | novel, serial, franchise timeline | continuity, translation, adaptation rights |
| Litany | oath book, ritual language, songs | performance rights, cultural safety |

Each publishing package should define:

- Who owns the work.
- What sources and model tools contributed.
- What can be remixed.
- What can be sold.
- What requires attribution.
- What is private, staged, public, or locked canon.
- What metadata is needed for discovery and distribution.

## AI-Era Rights Standard

Arcanea should adopt a visible rights standard for every serious artifact:

| Field | Meaning |
|---|---|
| Creator | Human author, artist, editor, or team. |
| Agent contribution | Which AI systems helped and how. |
| Source permissions | What references, datasets, or licensed works were used. |
| Training permission | Whether the artifact may be used for future training or fine-tuning. |
| Derivative permission | Whether remixes, sequels, translations, games, or adaptations are allowed. |
| Commercial permission | Whether money can be made from derivatives. |
| Attribution rule | How credit must appear. |
| Territory/format | Where and in what media the rights apply. |
| Canon status | Private draft, staged lore, public canon, licensed derivative, or locked canon. |
| Provenance anchor | Optional on-chain or signed record. |

This makes Arcanea credible to authors, publishers, artists, licensors, and AI builders.

## Language Rules

Use this language:

- "right use" instead of "unlock more power"
- "gift" instead of "drop" when the artifact carries duty
- "provenance" instead of "hype"
- "license" instead of "permission vibe"
- "world memory" instead of "content storage"
- "living world" instead of "AI content farm"
- "creator-owned IP" only when ownership and licensing are actually clear
- "lawful remix" when derivatives are permitted and attributed
- "publishing house" when editorial, metadata, rights, and distribution exist

Avoid this language:

- "unlimited magic"
- "fully autonomous canon"
- "NFT publishing" as the headline
- "AI owns the story" unless a legal and product structure actually supports it
- "sacred" for real cultures unless sensitivity review has been done
- "open IP" when the license is not explicit

## Anti-Trope Moves

| Generic version | Arcanea move |
|---|---|
| The hero gets a gift and becomes stronger. | The gift reveals a responsibility the hero cannot unknow. |
| The wizard explains the plot. | The Great Wizard names the cost and assigns one right-sized trial. |
| The AI generates a world. | The World Engine creates a coherent seed, then SIS records constraints and changes. |
| The book becomes an NFT. | The publishing house creates a rights-aware edition with metadata, license terms, and provenance. |
| Fans can remix anything. | Readers can become lawful co-creators inside clear canon, license, and attribution boundaries. |
| Magic has no limits. | Every power has cost, consent, consequence, and continuity. |

## Continuity Boundary

This doctrine is a system and writing layer. It does not lock new canon.

- It does not add a new deity.
- It does not redefine the Ten Gates.
- It does not make the Great Wizard a required character.
- It does not promote every draft to public canon.
- It does not require every artifact to be on-chain.

It gives Arcanea a world-class spine for June 2026 and beyond: magic as disciplined power, publishing as rights-aware world stewardship, SIS as memory, and Web3 as quiet provenance infrastructure.
