# Arcanea Orchestrator — Quickstart

**5 minutes from zero to routing tasks across Claude + OpenCode + Codex + Gemini.**

The Arcanea Orchestrator is a headless brain that picks the right AI coding CLI for each task, respects your subscription mix (Max, BYOK, free), and keeps a local history so it can learn which combinations actually work.

## What you'll have after this

- `arcanea-orchestrator` (and short `arco`) installed globally
- One config file at `~/.arcanea/config.yaml` (auto-generated by doctor)
- A running log at `~/.arcanea/history.jsonl` (grows as you use it)
- Zero data leaves your machine — prompts go direct from your shell to whichever CLI you chose

---

## 1. Install (30 seconds)

You need Node.js 20+ and one of the four AI CLIs installed (more is better — the orchestrator just delegates). Then:

```bash
npm i -g @arcanea/orchestrator
```

That installs two commands: `arcanea-orchestrator` (canonical) and `arco` (short alias). They do exactly the same thing.

Verify:

```bash
arco --version       # → 1.2.0 or higher
```

---

## 2. Detect what you have (30 seconds)

```bash
arco doctor
```

You'll see something like:

```
claude     sub                  /path/to/claude
opencode   free                 /path/to/opencode
codex      byok                 /path/to/codex
gemini     unknown              /path/to/gemini
```

- **sub** = You're logged into Claude Max — `claude -p` will use unlimited Opus/Sonnet/Haiku.
- **free** = OpenCode Zen works out of the box, no key needed.
- **byok** = Environment key detected (`OPENAI_API_KEY` for codex, `GOOGLE_API_KEY` for gemini).
- **unknown** = CLI installed but no key detected — set one to use it.

Auth hints print below the table if anything's missing.

---

## 3. Pick your preference (optional, 15 seconds)

```bash
arco config preference sub-first      # default — Max-sub first, then BYOK, then free
arco config preference free-first     # free tier first (Zen models)
arco config preference byok-first     # BYOK-first (saves your Max quota)
arco config preference cheapest       # same as free-first
```

---

## 4. First run (15 seconds)

```bash
arco run --task nav.fast "say hi in three words"
```

You'll see:

```
  [arcanea] task=nav.fast surface=claude-arcanea pref=sub-first → claude-haiku-4-5 via claude [auth: sub]
hi there friend
```

What happened:
1. Orchestrator looked up task class `nav.fast` in its spec.
2. Picked `claude-haiku-4-5` because it's fast and cheap.
3. Mapped to `claude` runtime (since Anthropic → claude CLI).
4. Execed `claude -p "say hi in three words" --model claude-haiku-4-5`.
5. Streamed output back.
6. Logged the event to `~/.arcanea/history.jsonl`.

---

## 5. Explore the routing logic

```bash
arco list-tasks                     # All 16 task classes
arco explain world.canon            # For this task, which models get picked?
arco explain code.debug --surface oh-my-arcanea    # Same but for free-tier surface
arco status                         # Full dashboard (spec + config + auth + AO + worktrees)
```

---

## 6. Decompose a big goal (Phase 5, Planner)

```bash
arco plan "add a /pricing page with 3 tiers"
```

You'll get a JSON plan with 3-7 sub-tasks, each mapped to a task class with a concrete prompt. Save it:

```bash
arco plan "add a /pricing page with 3 tiers" --out pricing-plan.json
```

Then dispatch each task one at a time (read `pricing-plan.json`, run its prompt):

```bash
arco run --task research.quick "<prompt from task 1>"
arco run --task docs.write "<prompt from task 2>"
arco run --task code.frontend "<prompt from task 3>"
# ... etc
```

---

## 7. Use a workflow template (batteries included)

```bash
arco workflow list
arco workflow show build-landing-page
arco workflow run build-landing-page --var page=/features --var pitch="..."
```

Workflows are pre-written compositions — variables fill in, orchestrator emits the expanded JSON plan. Pipe to `jq` for extraction, or dispatch manually.

---

## 8. See the data grow (Phase 6, Reasoning Bank)

After a handful of runs:

```bash
arco history                 # last 20 events in a table
arco history --json | jq     # pipe-friendly
arco stats                   # per-task → model success rates
arco learn code.debug        # baseline vs adaptive ranking with stats
```

Once you have ≥10 events, **adaptive routing** kicks in automatically (Phase 8). Candidates get re-ranked by local success rate + speed + recent-failure penalty — never overriding your tier preference, just ordering within it.

## Common pitfalls

**`arco: command not found`**
Global npm bin is not on PATH. Fix:
```bash
echo "export PATH=\"$(npm bin -g):\$PATH\"" >> ~/.bashrc  # adjust for zsh/fish
```

**`doctor` shows `claude: not installed` but you have it**
`where claude` (Windows) / `which claude` (Unix) must find it. If installed via a non-standard path, add to PATH.

**`run` hangs for 3+ seconds**
Some sub-CLIs wait on stdin. The orchestrator passes `stdin: ignore` for `plan`, but `run` uses `inherit` to preserve interactive prompts. If you hit this, pipe `< /dev/null`:
```bash
arco run --task X "..." < /dev/null
```

**`explain` or `run` says "no model resolved"**
The task + surface combination filtered out everything. Check:
- Is the surface's `authContext` compatible with your `preference`? (`claude-arcanea` needs `sub` or `byok`, so `free-first` with no Max sub won't route there.)
- Are any of the candidates available? Run `arco explain <task>` to see the candidate list.

**Claude Code slash `/ao` vs terminal `arco`**
`/ao` in Claude Code chat = promotion workflow skill. `arco` in terminal = this CLI. Totally different. The `/arco` skill in Claude Code wraps `arco` usage from within chat.

## What's under the hood

| File | What |
|---|---|
| `~/.arcanea/config.yaml` | Your preference + detected auth |
| `~/.arcanea/history.jsonl` | Every `run` event (append-only, rotates at 10 MB) |
| `@arcanea/router-spec/models.yaml` | Bundled routing spec (14+ models, 16 tasks, 7 surfaces) |

You can edit the config yaml directly. The router spec is in the npm package — edit your install's copy at your own risk, or fork it and publish your own `@yourscope/router-spec`.
