"Instead of having your AI re-read raw documents every time, have the AI incrementally build and maintain a persistent wiki — a structured, interlinked collection of markdown files that compounds over time." — Andrej Karpathy, April 2026

1. Core Principles (Karpathy + Frank Hybrid)

1
Wiki Over RAG
Don't re-read raw docs. AI maintains a persistent, structured, interlinked markdown wiki that compounds knowledge over time. Every session leaves the wiki smarter.
2
One Brain, Many Brands
Single knowledge graph spans all brands (Arcanea, FrankX, SIS, Music, Academies). Cross-pollination is a feature, not a bug. A lesson learned in Arcanea engineering applies to SIS consulting.
3
Each Brand Gets Full Stack
Local folder + GitHub repo + Notion hub + Linear project + Google Drive folder + wiki section. Standardized naming. No exceptions.
4
Agent-Native from Day 1
Every surface is designed for AI agents to read, write, and maintain. Markdown wiki = primary substrate. Notion/Linear/Drive = team interfaces. Agents grow the wiki; humans harvest insights.
5
Local-First, Cloud-Synced
Local folders are source of truth for code + wiki. Cloud tools (Notion, Linear, Drive) are team interfaces + backup. Google Drive = primary media storage. Cloudflare R2 = future CDN.
6
Obsidian = Personal Lens
Obsidian vault is Frank's personal journal, reflections, book notes, and creative sparks. It feeds INTO the wiki but is not the wiki itself. Private thoughts stay private.

Key Design Decisions

Wiki Location: Business/wiki/

The wiki lives under Business/ because it spans ALL brands. It's not owned by any single repo. Business/ = holding company = parent of all brands. Agents in any workspace can read/write to it via path reference.

Each Brand Has CLAUDE.md

When an agent opens any folder (Arcanea, FrankX, SIS, Music), it reads that brand's CLAUDE.md first. This file contains: brand identity, Notion hub ID, Linear project ID, Google Drive folder ID, wiki section path, naming conventions.

Media Strategy

Local media/ folders for active work. Google Drive for archival + sharing. Future: Cloudflare R2 for CDN delivery of published assets (book covers, course thumbnails, product images).

Obsidian ≠ Wiki

Obsidian = Frank's private thoughts, journal, reflections. Wiki = shared knowledge that agents can access and grow. Personal insights flow FROM Obsidian INTO wiki when they become actionable. Never the reverse.

8. Agent Maintenance Protocol

Daily Agent Pass (9am, automated)

1Read Linear active issues → update wiki/*/blockers.md
2Read planning-files/CURRENT_STATE → update wiki/business/gate-system.md
3Check revenue status → update wiki/arcanea/revenue-path.md
4Count wiki articles + words → update wiki/meta/growth-log.md
5Create interlinks between new and existing articles

Weekly Agent Pass (Sundays, automated)

1Harvest Obsidian ideas/ → wiki/learnings/ (new articles)
2Scan Notion hubs → update wiki overviews
3Review git log (all repos) → update wiki changelogs
4Prune stale articles (>30 days without update → flag for review)
5Generate wiki health report: coverage, gaps, staleness
6Cross-pollinate: find patterns across brands → wiki/learnings/
