## Promotion law

The Constellation is an evidence interface before it is an image gallery. A planned contract is not a generated image; a generated image is not approved; an approved image is not published. No preview or production surface may collapse those states.

The ignored internal workbench, blind-review keys, rejected media, preflight receipts, execution grants, provider receipts, and private creator files never enter a deployment artifact. Only exact public-safe teaching files and hash-linked, human-approved image bytes may reach the web tree.

## Gate A — deterministic source proof

Required evidence:

- `pnpm arcanea:visual:source:verify -- --file <creator-source-path>` passes for each private proposal used by a contract.
- `pnpm arcanea:visual:prior-evidence -- --json` passes before any prior Resonant Kinforms asset is nominated, and its packet-path warning is repaired before ingest.
- `pnpm arcanea:visual:verify` passes without changing current manifest hashes on a second run.
- `pnpm arcanea:visual:typecheck` passes in an installed canonical workspace.
- `git diff --check` passes.
- The generated/source prompt pairs, local source bytes, provider packets, current manifest index, schemas, and truth counts agree.
- No campaign image or receipt exists unless readiness names the exact authorized job.

Failure response: stop. Rebuild derivatives only after deciding whether the source change is a correction, a new proposal, or a canon change. A changed source digest creates a new contract set and new immutable manifests; it never rewrites earlier lineage.

## Gate B — public artifact boundary

Inspect the deployment file graph and prove:

- `planning-with-files/arcanea-visual-workbench/` is ignored and absent from build output;
- `planning-with-files/arcanea-visual-assets/`, blind-review packets, authority receipts, and private keys are absent;
- public contracts contain repository-relative labels and digests, never `C:\Users\...`, Downloads paths, environment values, API keys, or provider receipts;
- provider credentials are headers or server runtime secrets, never URLs, HTML, client bundles, or logs returned to anonymous users;
- every rendered image URL comes from an approved or published campaign state.

Failure response: remove the leaking artifact or route from the preview before further review. Credential leakage is a release blocker, not a copy defect.

## Gate C — route and information architecture proof

Build once under an allowed machine posture, then crawl the complete planned route set. Require:

- 200 responses for all 167 routes;
- one canonical URL and unique title per route;
- no orphan dossier, prompt contract, Guardian, Godbeast, character, or world;
- `/gallery` → `/constellation` and `/constellation` → `/gallery` handoff;
- sitemap inclusion for every intended public route and exclusion of internal evidence;
- working AGENT.md, SKILL.md, card, contract, audit, and open-decision downloads;
- truthful empty-media states with no broken `Image` source;
- one obvious primary action in the first viewport and no decorative portal that hides campaign state.

Failure response: hold preview promotion and fix routing/data derivation. Never hand-maintain a second route list.

## Gate D — desktop, mobile, and accessibility proof

On the Vercel preview, capture the atlas plus representative agent, Guardian, Godbeast, character, world, and prompt routes at narrow mobile, wide mobile, tablet, laptop, and large desktop widths. Inspect both light and dark user preferences where the product supports them.

Require:

- complete keyboard traversal with visible focus and logical order;
- usable details/summary controls and links without pointer input;
- headings, landmarks, names, states, and approval boundaries announced coherently by a screen reader;
- text and controls remain usable at 200% zoom and with long readiness labels;
- reduced-motion preference removes nonessential movement while all content remains present;
- no horizontal overflow, clipped evidence, layout shift from absent media, or unreadable microcopy;
- color is never the sole carrier of identity, readiness, blocked state, or score;
- approved media has specific alt text; decorative/evidence placeholders do not masquerade as images.

Failure response: fix and repeat the affected viewport plus one adjacent viewport. Do not promote from source inspection alone.

## Gate E — quality and claim proof

Read every first-viewport claim and a generated sample across all dossier families. Require:

- counts derive from versioned data;
- `Contract-ready`, `Gated`, and `Generated` remain distinct;
- Prismatic is the public face of one operational role, not a seventeenth identity;
- Luminor is described as a rank or operating concept where appropriate, never silently as a species;

- no identity is called locked before the eight-view qualification chain exists;

Failure response: correct the source data or contract, regenerate public derivatives, and rerun deterministic gates. Do not patch only the rendered sentence.

## Gate G — human release decision

The decision record must name:

- brand approver and accepted visual direction;
- canon and identity approvers;
- rights and likeness evidence;
- required cultural or lived-experience specialist evidence;
- exact approved asset hashes, crop set, and alt text;
- accepted preview URL and verification packet;
- production promoter, time, rollback owner, and monitoring window.

Production promotion remains a distinct human action. DNS, secrets, billing, spend, permissions, and legal/IP decisions are never implied by this packet.

## Rollback and supersession

- Before media approval: remove the Constellation navigation/sitemap entries or revert the route slice; existing `/gallery` remains intact.
- After media approval but before publication: remove only the staged exact public bytes and approval pointer; preserve internal receipts and rejected history.
- After publication: restore the last accepted deployment, record the rollback evidence, and mark the superseded publication receipt without deleting lineage.
- A visual-identity correction creates a new version and explicit supersession link. Never alter an old receipt or silently replace bytes at the same evidence identity.
