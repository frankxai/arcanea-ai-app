# Arcanea Operating System

Status: execution doctrine. This document does not modify locked canon. It turns the current Arcanea thesis into a business, product, agent, and SDLC operating model.

Updated: 2026-06-26

## One-Line Strategic Read

Arcanea should be operated as a living-universe company, not a route collection: one unforgettable Genesis doorway, a creator-owned world substrate, a paid Forge layer, and an evidence-driven agent team that turns worlds into publishable, rights-aware products.

## The Prime Constraint

Arcanea has more imagination than proof. The next phase must convert breadth into one measurable transformation:

```text
Creator intent -> First Gift -> living world seed -> proof artifact -> owned repo/world memory -> publishable package
```

Everything that does not strengthen this path is deferred, hidden, or routed to the substrate.

## Operating Principles

1. One front door wins: "speak a world into existence" is the public product.
2. Myth serves usefulness: chosen language means responsibility, not superiority.
3. Worlds are owned: repo-canonical, portable, provenance-aware, and exportable.
4. Agents are workers, not mascots: every agent has a task, evidence, owner, and stop rule.
5. Metrics change decisions: no vanity dashboards without a weekly operating decision.
6. Canon and commerce stay cleanly separated: lore can inspire offers, but checkout, rights, and support need plain boundaries.
7. No dark-pattern devotion: Arcanea earns return use through useful proof, memory, publishing leverage, and creator success.

## North Star And Guardrails

North Star:

```text
Activated worlds with a completed proof artifact and portable memory record.
```

Core activation metric:

```text
first_gift_completed / first_session_started
```

Quality guardrails:

- Time to first Gift under 90 seconds for the fast path.
- Creator can export or understand ownership by the end of the first session.
- Every generated world has at least one law, one cost, one visual DNA seed, one character, and one next proof action.
- Claims about crisis, rights, or AI capability are source-grounded.
- No human group is cast as the enemy; The Drift is a condition.

## Product Operating Model

The product team should work in four loops.

| Loop | Cadence | Owner | Output | Acceptance gate |
|---|---|---|---|---|
| Genesis loop | Daily until MVP | Product + World Engine | First Session flow | User creates Gift, world seed, and proof. |
| Forge loop | Weekly | Creator Forge | Paid package or launch asset | Buyer, deliverables, rights, checkout path. |
| Canon loop | Weekly | Canon Director | Continuity improvements | No conflict with locked canon. |
| Evidence loop | Weekly | SIS/Growth | Metrics, evals, decisions | One decision logged per metric review. |

## Agentic Team Model

Use agents as bounded specialists with traceable outputs. The default team:

| Agent | Job | Inputs | Output | Stop rule |
|---|---|---|---|---|
| Source Scout | Ground claims and references. | Topic, claims, allowed sources. | Source packet and risk flags. | Enough evidence for decision or explicit uncertainty. |
| Canon Director | Protect Arcanea coherence. | Locked canon, staged lore, draft. | Continuity verdict and repair options. | No silent canon changes. |
| World Builder | Generate coherent worlds. | Intent, Gift Object, constraints. | World bible seed. | Must include laws, costs, conflict engine, visual DNA. |
| Right Use Reviewer | Check consent, rights, cultural safety. | Artifact, sources, intended use. | Pass/revise/block verdict. | Any unclear rights blocks commercialization. |
| Product Strategist | Turn doctrine into UX. | Strategy, target user, constraints. | PRD, tickets, acceptance criteria. | Every screen maps to activation metric. |
| Growth Analyst | Measure funnel and experiments. | Events, traffic, cohorts. | Dashboard spec and decisions. | Metrics tied to owner and action. |
| QA Critic | Break the work. | Build, PRD, rubric. | Defects and residual risk. | No critical defects open for release. |
| SIS Steward | Preserve decisions and provenance. | Outputs, evals, sources. | Memory record and ledger entry. | Durable path and owner recorded. |

## Agent Workflow Patterns

Use the simplest workflow that fits the task.

| Pattern | Use when | Arcanea example |
|---|---|---|
| Prompt chain | The task has ordered steps. | Intent -> Gift -> World Bible -> Proof Artifact. |
| Routing | Inputs need specialist handling. | Lore, rights, UI, growth, and support requests. |
| Parallelization | Independent checks improve confidence. | Canon, design, safety, and growth reviews in parallel. |
| Orchestrator-workers | The shape is unknown upfront. | Multi-repo release audit or world package sprint. |
| Evaluator-optimizer | Quality bar matters more than latency. | Premium visual, homepage copy, onboarding outputs. |

## SDLC For Arcanea Work

Every meaningful product change should follow this path:

```text
Brief -> source/canon check -> PRD -> design contract -> implementation -> tests -> eval -> preview -> release note -> SIS decision record
```

Minimum task contract:

```text
Scope:
Owner:
Files:
Non-goals:
Acceptance criteria:
Verification:
Rollback:
Metrics:
Risk review:
```

Release gates:

1. Typecheck/build pass for touched app or package.
2. UI checked at desktop and mobile if visual.
3. Event instrumentation is specified for activation work.
4. Rights/canon review complete for publishable artifacts.
5. Preview URL verified before production when deployment is in scope.

## Business Operating Cadence

Daily:

- Ship one proof-sized improvement to Genesis, Forge, or Fabric.
- Log blockers that prevent revenue or activation.

Weekly:

- Review activation, conversion, retention, and proof artifacts.
- Decide one thing to build, one thing to cut, one thing to sell.
- Move one world/product from draft to package-ready.

Monthly:

- Review offer ladder, creator feedback, cost per activation, and catalog health.
- Update the public promise only if product proof supports it.

| P1 SIS memory records | The moat is durable memory/provenance. | Persist Gift, source, rights, canon status, evals. |
| P2 Route consolidation | Sprawl weakens brand and engineering. | Hide or subordinate routes outside Genesis. |
| P2 Visual canon | Premium perception needs coherent media. | Build prompt suite and QA gate for Genesis visuals. |

## Kill Or Defer

Defer until First Session activation is real:

- More public route expansion.
- Lore pages that do not feed Genesis, Forge, or publishing.
- On-chain UX as a headline.
- New social/community systems without proof artifacts to share.
- Additional agent brands without task ownership and evidence.
