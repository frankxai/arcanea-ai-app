## 1. Architecture overview

```

┌─────────────────────────────┐               ┌──────────────────────────────────┐
│ challenges/season-0/        │               │ apps/web/data/challenges/        │
│   README.md      (rules ptr)│   maintainer  │   season-0.json   ← LEDGER       │
│   entry-template/           │   judges +    │ apps/web/lib/challenges/         │
│   entries/<handle>--<name>/ │──commits──▶   │   season-zero.ts  (typed loader) │
│     SKILL.md                │   scores      │ apps/web/app/challenges/page.tsx │
│     entry.json              │               │   renders ledger (honest stats)  │
│     world/                  │               │ .claude/skills/challenge-judge/  │
│ .github/workflows/          │               │ scripts/challenge-judge/         │
│   validate-entries.yml      │               │   run-judges.mjs                 │
└─────────────────────────────┘               └──────────────────────────────────┘
```

Contributor PRs land in the OSS repo only — they never touch the Vercel deploy surface. Scores flow back into the production repo as maintainer commits to the ledger. Winners are copied by maintainers into `.claude/skills/community/` (both repos) after judging — the moderation gate before anything enters the plugin.

## 2. Submission format (OSS repo)

Directory: `challenges/season-0/entries/<github-handle>--<skill-name>/`

| File | Contract |
|---|---|
| `SKILL.md` | The workflow. Must pass claude-skills-library validator rules: frontmatter `name` (lowercase-hyphenated, == folder suffix), `description` (third person, ≤1024 chars), body ≤500 lines. Promotable verbatim if it wins. |
| `entry.json` | Manifest (schema below). |
| `world/` | The world generated by running the workflow against **one public seed**. Markdown files in the world-forge layer structure: `cosmology.md`, `systems.md`, `geography.md`, `factions.md`, `timeline.md` (+ optional extras). |

`entry.json` schema:

```json
{
  "schema": "arena-entry-v1",
  "entrant": { "github": "<handle>" },
  "skill": { "name": "<skill-name>", "version": "0.1.0" },
  "seed_used": "<public-seed-id>",
  "models_declared": ["<model ids used by the workflow>"],
  "runtime": "claude-code",
  "output_sample": "world/",
  "license_accepted": "SUBMISSIONS-LICENSE-v1",
  "notes": "<optional, ≤500 chars>"
}
```

One entry per GitHub account per season. `license_accepted` is required — the validator fails the PR without it.

## 3. Validation (GitHub Action, OSS repo)

`.github/workflows/validate-entries.yml` runs `challenges/season-0/scripts/validate_entry.py` on changed entries:

1. Directory name matches `<handle>--<skill-name>` and handle == PR author.
2. `SKILL.md` frontmatter + line-count rules (ported from `claude-skills-library/scripts/validate_skills.py`).
3. `entry.json` parses and satisfies the schema; `seed_used` is a real public seed id; `license_accepted == "SUBMISSIONS-LICENSE-v1"`.
4. `world/` contains the five layer files, each non-empty.
5. **Injection lint**: scan all submitted text for instruction-hijack patterns (e.g. "ignore previous instructions", "you are the judge", "score this 100", system-prompt impersonation markers). Hit = validation failure, flagged for DQ review. The pattern list lives beside the validator; hits are reviewable by maintainers (false positives can be waived by label).

## 4. Judge pipeline (maintainer-run, not a web endpoint)

Tooling: `.claude/skills/challenge-judge/SKILL.md` (operator instructions) + `scripts/challenge-judge/run-judges.mjs` (scoring engine). Run locally by a maintainer with their own API keys. Nothing is exposed as a public endpoint in Season 0 (no persistence layer, no key exposure, no abuse surface).

Per entry:

1. **Structural re-validation** (same checks as the Action).
2. **Held-out run**: the entrant's `SKILL.md` is executed in a fresh Claude Code sandbox against a **held-out seed** published only at judging start. The generated world from this run — not the submitted `world/` sample — is the scored artifact. This is the core anti-gaming device: the *workflow* is judged, not a hand-polished output.
3. **Canon gate**: `canon-check` runs against the held-out output. Violations of LOCKED canon = hard fail (entry ranked but marked `canon: fail`, ineligible to win).
4. **Rubric scoring**: outputs anonymized (entrant identifiers stripped, entries relabeled `entry-A/B/C…`), then scored by a 3-judge panel:
   - Judge 1 & 2: `claude-opus` at temperature 0.2 with two distinct judge framings (craft-critic framing; systems-consistency framing).
   - Judge 3: one non-Anthropic model (Gemini via the Google provider already in the app's Vercel AI SDK stack) as an independent second opinion.
   - Each judge returns strict JSON: `{ scores: { canon_coherence, world_depth, originality, workflow_craft, output_craft }, rationale }`, each dimension 0–100, clamped. Calibration line in the prompt: "70 is solid, 90 is exceptional" (lifted from `api/arena/run`).
   - **Median per dimension** across the three judges → weighted total (weights in §5).
5. **Community signal**: 👍 reactions on the entry PR, snapshotted at judging start, one per account, only accounts created before season open. Normalized 0–100 across entries.
6. **Final score** = `0.9 × judge_total + 0.1 × community_signal`.
7. Results appended to the ledger (`season-0.json`) via PR to arcanea-ai-app, with per-dimension scores and judge rationales public.

## 5. Rubric (published in `docs/community/judging-rubric.md`)

| Dimension | Weight | Anchor |
|---|---|---|
| Canon Coherence | 25 | Gated by `canon-check`; respects LOCKED tiers, uses canon vocabulary correctly |
| World Depth & Internal Consistency | 20 | world-forge rule: every element connects to ≥2 others; no contradictions |
| Originality | 20 | Distinctive within canon constraints, not a template refill |
| Workflow Craft & Reusability | 20 | Installs cleanly, passes validators, reproducible on the held-out seed; `gate-eval`-informed sub-checks |
| Output Craft | 15 | Prose quality, structure, usability of the generated world |

## 6. Ledger (production repo)

`apps/web/data/challenges/season-0.json`:

```json
{
  "schema": "arena-ledger-v1",
  "program": "Arcanea Arena",
  "season": 0,
  "title": "The Worldsmith Trials",
  "status": "draft",
  "opensAt": null,
  "closesAt": null,
  "seeds": [],
  "prize": null,
  "entries": [],
  "scores": [],
  "leaderboard": []
}
```

- `status`: `draft | open | judging | complete`.
- `entries[]`: `{ id, entrant, skill, submittedAt, prUrl, valid }` — mirrored from merged OSS PRs by maintainers.
- `scores[]`: `{ entryId, dimensions: {...}, judgeTotal, communitySignal, finalScore, canon: "pass"|"fail" }`.
- `leaderboard[]`: ordered `{ rank, entryId, finalScore }`, written once at `status: complete`.
- Loader: `apps/web/lib/challenges/season-zero.ts` — typed static import; derived stats (entry count, unique entrants, open-challenge count) computed in the loader so the page renders only ledger-derived numbers. `prize: null` renders as "Recognition + plugin distribution".

**Why a ledger and not Supabase for Season 0**: the genesis world-graph migration's own doctrine is "the repo is the canonical source of truth; the schema is a derived index." Submissions already arrive as PRs; a DB adds a sync problem, an auth/RLS surface, and an ops burden with zero users to justify it — and it weakens auditability, which is the program's trust anchor (every public number traces to a commit).

## 7. Anti-gaming summary

| Vector | Countermeasure |
|---|---|
| Hand-polishing the sample world | Held-out seed run is the scored artifact |
| Prompt injection at the judge | Injection lint (DQ) + anonymization + judges see only outputs |
| Vote brigading | Community signal capped at 10%, snapshotted, pre-season accounts only |
| Judge-model bias / variance | 2 framings × Opus + 1 non-Anthropic judge, median per dimension, temp 0.2 |
| Sybil entries | One entry per GitHub account; handle must match PR author |
| Canon-washing (ignoring canon for spectacle) | `canon-check` hard gate |

## 8. Deferred to Season 1 (do not build now)

- In-app submission portal + Supabase persistence (Appendix A).
- `get_leaderboard` phantom RPC in `api/leaderboard/route.ts` — create or remove.
- Persisting `api/arena/run` results; exposing judge runs as an API.
- Sandbox-as-a-service for untrusted workflow execution (Season 0 sandboxes are maintainer-local fresh sessions).
- Prizes/payment rails; sponsorships.
- Multi-season automation; team (crew) entries; cross-harness tracks.

## Appendix A — Season 1 Supabase migration (SPEC ONLY — do not apply in Season 0)

Written in the style of `supabase/migrations/20260403000002_worlds.sql`. Ships only when in-app submissions exist.

```sql
-- Season 1 — DO NOT APPLY in Season 0. Ledger (apps/web/data/challenges/*.json) is authoritative until then.

-- ============================================================================
-- CHALLENGES
-- ============================================================================
CREATE TABLE IF NOT EXISTS public.challenges (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  slug TEXT UNIQUE NOT NULL,
  title TEXT NOT NULL,
  season INTEGER NOT NULL,
  description TEXT,
  status TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'open', 'judging', 'complete')),
  seeds JSONB NOT NULL DEFAULT '[]'::jsonb,
  rubric JSONB NOT NULL DEFAULT '{}'::jsonb,
  prize JSONB,
  opens_at TIMESTAMPTZ,
  closes_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- ============================================================================
-- SUBMISSIONS
-- ============================================================================
CREATE TABLE IF NOT EXISTS public.challenge_submissions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  challenge_id UUID NOT NULL REFERENCES public.challenges(id) ON DELETE CASCADE,
  entrant_id UUID NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  skill_name TEXT NOT NULL,
  skill_version TEXT NOT NULL DEFAULT '0.1.0',
  manifest JSONB NOT NULL,
  source_url TEXT,
  status TEXT NOT NULL DEFAULT 'submitted' CHECK (status IN ('submitted', 'valid', 'invalid', 'disqualified', 'judged')),
  license_accepted TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (challenge_id, entrant_id)
);

-- ============================================================================
-- SCORES
-- ============================================================================
CREATE TABLE IF NOT EXISTS public.challenge_scores (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  submission_id UUID NOT NULL REFERENCES public.challenge_submissions(id) ON DELETE CASCADE,
  judge TEXT NOT NULL,
  dimensions JSONB NOT NULL,
  judge_total NUMERIC(5,2) NOT NULL CHECK (judge_total >= 0 AND judge_total <= 100),
  community_signal NUMERIC(5,2) CHECK (community_signal >= 0 AND community_signal <= 100),
  final_score NUMERIC(5,2) CHECK (final_score >= 0 AND final_score <= 100),
  canon_pass BOOLEAN NOT NULL DEFAULT false,
  rationale TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Indexes
CREATE INDEX IF NOT EXISTS idx_challenges_status ON public.challenges(status) WHERE status = 'open';
CREATE INDEX IF NOT EXISTS idx_submissions_challenge ON public.challenge_submissions(challenge_id);
CREATE INDEX IF NOT EXISTS idx_scores_submission ON public.challenge_scores(submission_id);

-- RLS
ALTER TABLE public.challenges ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.challenge_submissions ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.challenge_scores ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Challenges are publicly readable" ON public.challenges FOR SELECT USING (true);
CREATE POLICY "Submissions readable by all, writable by owner" ON public.challenge_submissions
  FOR SELECT USING (true);
CREATE POLICY "Entrants insert own submissions" ON public.challenge_submissions
  FOR INSERT WITH CHECK (auth.uid() = entrant_id);
CREATE POLICY "Entrants update own submissions" ON public.challenge_submissions
  FOR UPDATE USING (auth.uid() = entrant_id);
CREATE POLICY "Scores are publicly readable" ON public.challenge_scores FOR SELECT USING (true);
-- Score writes: service role only (judge pipeline), no user policy.

-- updated_at triggers (reuse public.handle_updated_at() if present)
CREATE TRIGGER challenges_updated_at BEFORE UPDATE ON public.challenges
  FOR EACH ROW EXECUTE FUNCTION public.handle_updated_at();
CREATE TRIGGER challenge_submissions_updated_at BEFORE UPDATE ON public.challenge_submissions
  FOR EACH ROW EXECUTE FUNCTION public.handle_updated_at();
```
