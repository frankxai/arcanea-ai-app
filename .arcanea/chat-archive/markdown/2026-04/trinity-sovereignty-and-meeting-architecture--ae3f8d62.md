## How to structure this in your Notion

Right now you're trying to put everything in one Notion database. That's the source of the confusion. The correct structure is **three linked databases**.

### Database 1 — Intelligence Systems *(the protocol layer)*

One row per IS. Properties:
- Name (e.g., "Creator Intelligence System")
- Code (CIS, WIS, MIS, etc.)
- Status (Spec drafted / Reference built / Production / Maturing)
- Public repo URL
- Spec document URL
- Brief description
- Dependencies on other ISs
- Primary operator (relation → Database 2)
- Implementations (relation → Database 3)

Twelve rows total. This is the periodic table.

### Database 2 — Brands / Companies / Vehicles *(the commercial layer)*

One row per company or brand. Properties:
- Name (e.g., "FrankX", "Arcanea BV", "Trinity AI", "Starlight Intelligence Foundation")
- Type (BV / LLC / Foundation / DBA-brand / Sub-brand)
- Owner (Frank / Frank+Trinity / Trinity / external)
- Public website
- Status (Active / Planning / Future)
- ISs primarily operated (relation → Database 1)
- Products (relation → Database 3)
- Revenue model
- Notes

About 10–15 rows. This is the org chart of your empire.

### Database 3 — Products *(the customer-facing layer)*

One row per actual product or offering. Properties:
- Name (e.g., "ACOS Solo Pack", "Trinity Wealth Council", "Starlight Challenge Premium")
- IS this implements (relation → Database 1)
- Operating brand (relation → Database 2)
- Path tier (Free / Path A / Path B / Path C / Subscription)
- Pricing
- LemonSqueezy URL
- Buyer archetype
- Status (Concept / Building / Live / Maturing)
- Affiliate partners
- Notes

This grows over time — eventually 50+ rows as you build out the ecosystem. This is your storefront and roadmap rolled into one.

**The magic of the three-database structure:** every product is automatically tagged with its IS *and* its operating brand. You can filter views like "all products operated by Trinity AI" or "all products implementing Creator IS" or "all Path A products live on LemonSqueezy" — and the same row contributes to all three views. No more re-mapping required.
