- ✅ Easy to sync with Claude Code


**Why separate?**
- ✅ Can be used across ALL your brands (not just frankx.ai)

## 🤖 HOW TO BUILD IT (3 Options)

### **OPTION 1: Manual First, Automate Later** ⭐ RECOMMENDED START

**Week 1 - Manual Setup (2-4 hours):**

1. **Create the repo structure** (10 min)
   ```bash
   cd ~/code/frankx.ai  # or wherever
   mkdir content-inventory
   cd content-inventory
   touch music-catalog.md articles-catalog.md README.md
   git add .
   git commit -m "Initialize content inventory"
   git push
   ```

2. **Fill in what you remember** (1 hour)
   - Open `music-catalog.md`
   - Go to your Suno profile
   - Copy/paste 20-30 recent songs manually
   - Add: Title, Link, Genre, Date

3. **Batch process the rest** (2-3 hours)
   - Spend a Saturday afternoon
   - Go through your Suno library chronologically
   - Add entries in batches (10-20 at a time)
   - Use Claude to help format if needed

**Manual Process Example:**
```markdown
You: "Claude, here are 20 Suno links. Help me format them as markdown table entries with placeholders for BPM/mood that I'll fill later"

[paste 20 links]

Claude: [generates formatted table]

You: [copies into music-catalog.md, commits to GitHub]
```

**Pros:**
- ✅ Start immediately
- ✅ Forces you to review your work
- ✅ You discover forgotten gems
- ✅ Clean, intentional data

**Cons:**
- ❌ Takes 2-4 hours initial setup
- ❌ Ongoing manual updates

### **OPTION 2: Semi-Automated with n8n** ⭐ RECOMMENDED NEXT STEP

**How it works:**

```
New Suno Song Published
    ↓
n8n webhook detects it (or you trigger manually)
    ↓
Extracts: Title, Link, Genre from Suno
    ↓
Formats as markdown table row
    ↓
Appends to music-catalog.md in GitHub
    ↓
Auto-commits with message: "Add: [Song Title]"
    ↓
Sends you Telegram/Discord notification: "✅ Song logged!"
```

**Setup (1-2 hours if you know n8n):**

1. **Create n8n workflow:**
   - Trigger: Manual/Webhook (you paste Suno link)
   - HTTP Request: Scrape Suno page for metadata
   - Code: Format as markdown row
   - GitHub API: Append to file
   - Notification: Confirm to you

2. **Alternative: Use Make.com if easier**
   - Same logic, visual builder
   - Might be faster to set up

**Ongoing Process:**
```markdown
You publish song on Suno
    ↓
You paste link into n8n webhook URL (or Telegram bot)
    ↓
Song auto-logs to GitHub
    ↓
Done (5 seconds of work)
```

**Pros:**
- ✅ Much faster ongoing (5 sec vs 2 min per song)
- ✅ Consistent formatting
- ✅ Can backfill old songs in batch

**Cons:**
- ❌ 1-2 hours initial n8n setup
- ❌ Requires webhook/API knowledge

---

### **OPTION 3: Fully Automated with MCP Server** 🚀 FUTURE STATE

**How it works:**

```
Claude Code has GitHub MCP access
    ↓
You say: "Log my new song: [Suno link]"
    ↓
Claude Code:
  1. Fetches Suno metadata via scraping
  2. Reads music-catalog.md from GitHub
  3. Appends new entry
  4. Commits to GitHub
  5. Confirms to you
    ↓
Done (10 seconds, zero context switching)
```

**Or even better - Voice Note Automation:**

```
You: [voice note] "Hey, just published 'Thunder Strike' on Suno, hard rock track, 140 BPM, super aggressive"
    ↓
Transcription service → n8n
    ↓
n8n triggers Claude via API
    ↓
Claude:
  - Searches Suno for your latest upload
  - Matches "Thunder Strike"
  - Logs to GitHub with your voice note details
    ↓
Done (literally zero manual work)
```

**Setup Requirements:**
- GitHub MCP configured for Claude Code
- n8n workflow for voice processing
- Suno scraping (or unofficial API if it exists)

**Pros:**
- ✅ Zero friction
- ✅ Natural language input
- ✅ Works from anywhere (phone, computer)

**Cons:**
- ❌ Complex setup (4-6 hours)
- ❌ Requires multiple integrations
- ❌ Need to maintain if APIs change
